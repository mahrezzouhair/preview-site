# الدفع بالبطاقة (YouCan Pay) + التفعيل الأوتوماتيكي — دليل السيرفر

> **الحالة: كود مكتوب فقط — ما منشور ما متنشرش.**
> النشر ماشي من مهام هاد البناء، وخاصو قرار صريح من صاحب الموقع
> (ترقية Blaze + مفاتيح حقيقية). هاد الملف كيشرح فين كيمشي كل مفتاح
> وشنو باقي للإنتاج، باش ما يتخاد حتى قرار بالغلط.

## 1. كيفاش كتخدم المنظومة

```
المتعلم (payment.html، مسجل دخول)
  → createPayment (بـ ID token) → YouCan Pay tokenize → tokenId
  → نموذج yp.js في الصفحة (بالعربية، RTL) → المتعلم كيخلص بالبطاقة
  → YouCan Pay كيصيفط Webhook للسيرفر
  → السيرفر: توقيع HMAC + مبلغ + طلب → تسجيل approved في Firestore
  → إيميل تأكيد للمتعلم + الدورة كتبان مفعّلة في «دوراتي»
```

- **التحويل البنكي ما كيتمسش**: كيبقى يدوي (طلب pending → موافقة مدرب
  في الداشبورد). الدفع بالبطاقة هو مسار إضافي، ماشي بديل يلغي البنكي.
- **التفعيل الأوتوماتيكي غير للبطاقة**: Webhook متحقق منو فقط هو اللي
  كيكتب `status: 'approved'`. حتى طلب بنكي ما كيتفعّل أوتوماتيكياً.
- **الحمايات كتبقى**: بلا تحميل للفيديو + علامة مائية باسم المتعلم
  (المشغّل نفسه غادي يجي من بعد عبر Bunny Stream — ماشي هنا).

## 2. فين كيمشي كل مفتاح (مهم)

| المفتاح | فين كيمشي | فين ما يمشيش أبداً |
|---|---|---|
| المفتاح العمومي `pub_...` (ونسخة Sandbox `pub_sandbox_...`) | `youcan-config.js` (المتصفح) — عمومي بطبيعتو | — |
| المفتاح الخاص `pri_...` | أسرار الدالة فقط (`firebase functions:secrets:set YOUCAN_PRIVATE_KEY`) | أبداً في HTML/JS ديال المتصفح، ولا في Git، ولا في الشات |
| رابط الدالة `functionUrl` | `youcan-config.js` | — |
| بيانات SMTP ديال إيميل التأكيد | أسرار الدالة (`SMTP_HOST/USER/PASS/FROM`) | أبداً في كود المتصفح |
| رابط Webhook | إعدادات Webhook في لوحة YouCan Pay ولا عبر API | — |

إلا كان `functionUrl` خاوي ولا `publicKey` مازال PLACEHOLDER، صفحة
الدفع كتبيّن «الدفع بالبطاقة مازال ما تفعلش» وما كتبدا حتى عملية أداء.

## 3. شنو كيتحقق منو السيرفر قبل التفعيل (كلشي خاصو يدوز)

1. **رمز الدخول**: `createPayment` كيطلب Firebase ID token صالح، وuid
   ديالو هو اللي كيتسجل — ما يمكنش لشخص يخلق دفع لحساب آخر.
2. **منع الدفع المكرر**: إلا كانت الدورة `approved` أصلاً، الدالة
   كترجع 409 وما كتولدش رمز جديد.
3. **توقيع Webhook**: `X-YOUCANPAY-SIGNATURE` = HMAC-SHA256 للجسم
   الخام بالمفتاح الخاص، بمقارنة ثابتة الزمن. توقيع خاطئ = 403.
   الجسم الخام ضروري: إعادة ترميز JSON كيفشل التوقيع.
4. **نوع الحدث والحالة**: غير `transaction.paid` بحالة مدفوعة.
5. **وضع Sandbox/Production**: حدث Sandbox ما كيتقبلش في وضع
   الإنتاج والعكس.
6. **الطلب معروف**: `order_id` خاصو يطابق سجل `payment-orders`
   تولد عند `createPayment` (YouCan ما كيدعمش metadata مخصصة موثقة
   في Tokenize، لهذا الربط كيتم عبر سجلنا).
7. **المبلغ**: 499 درهم للدورة. ملاحظة وحدة المبلغ: توثيق Tokenize
   كيستعمل أصغر وحدة (49900)، بينما كائن Transaction في v2 كيستعمل
   الوحدة الكبيرة ("499.00"). الكود كيقبل القراءتين ديال نفس الثمن
   وكيسجل أنهي وحدة تطابقات — **في أول اختبار Sandbox حقيقي، أكد
   الوحدة وشدد القبول لوحدة وحدة**.
8. **إعادة قراءة دفاعية**: الدالة كتحاول تقرا المعاملة من
   `GET /api/v2/transactions` بفلتر `order_id`. إلا ناقضات السجل،
   التفعيل كيترفض. إلا تعذرات القراءة، التوقيع (آلية الثقة الموثقة)
   كافي. **أكد في أول اختبار أن فلتر order_id خدام**؛ إلا ما كانش،
   بدّل إعادة القراءة بطريقة أخرى قبل الإنتاج.
9. **منع التكرار**: سجل `payment-orders` كيتحول لـ `paid` مرة وحدة؛
   توصيل Webhook مكرر كيرجع 200 بلا تفعيل ثاني. وإلا كان طلب معلق
   لنفس الدورة (تحويل بنكي مثلاً)، كيترقى هو بلا ما يتضاعف التسجيل.

## 4. خطوات النشر (منين يقرر صاحب الموقع)

1. **فتح حساب YouCan Pay** (بيد صاحب الموقع: معلوماته + تأكيد
   الإيميل/الهاتف). من لوحة الحساب: خد مفاتيح Sandbox أولاً.
2. **ترقية مشروع Firebase لـ Blaze** — ضرورية: خطة Spark المجانية
   ما كتنشرش الدوال وما كتسمحش بالاتصال بخدمات خارج Google.
   Blaze كيحتفظ بالحصص المجانية (2 مليون استدعاء/شهر...) وكيخلص
   غير فوقها، لكن كيتطلب حساب فوترة/بطاقة مسجلة.
3. **تثبيت الأدوات ونشر الدوال** (من مجلد المشروع):
   ```
   npm install -g firebase-tools
   firebase login
   firebase use hijama-tracker
   firebase functions:secrets:set YOUCAN_PRIVATE_KEY
   firebase functions:secrets:set YOUCAN_PUBLIC_KEY
   firebase functions:secrets:set SMTP_PASS
   firebase deploy --only functions
   ```
   ومتغيرات البيئة الأخرى (`YOUCAN_MODE`, `SITE_URL`,
   `ALLOWED_ORIGINS`, `SMTP_HOST/USER/FROM`) كتتسجل في إعدادات
   الدالة / `.env` ديال Functions.
4. **تسجيل رابط Webhook** في لوحة YouCan Pay (إعدادات Webhook) ولا
   عبر `POST /api/v2/webhooks`:
   `https://europe-west1-hijama-tracker.cloudfunctions.net/youcanWebhook`
5. **ربط المعاينة**: عمّر `youcan-config.js` بـ `publicKey` ديال
   Sandbox ورابط `createPayment`، وجرّب أداء Sandbox كاملاً
   (بطاقة اختبار) وتأكد من: التفعيل في «دوراتي» + الإيميل + سجل
   `payment-events` + عدم تضاعف التسجيل عند إعادة التوصيل.
6. **شدّد وحدة المبلغ** (نقطة 7 أعلاه) حسب نتيجة اختبار Sandbox.
7. **قفل Firestore**: منع كتابة العملاء في `payment-orders` و
   `payment-events` (الكتابة خاصة بالسيرفر عبر Admin SDK فقط).
   التسجيلات `course-enrollments` كتبقى بقواعدها الحالية.

## 5. خطوات التبديل للإنتاج (منين يوجد الدومين)

1. في لوحة YouCan Pay: بدّل مفاتيح Sandbox بمفاتيح الإنتاج.
2. في أسرار الدالة: `YOUCAN_MODE=production` + المفتاح الخاص
   ديال الإنتاج + `SITE_URL` بالدومين الجديد + `ALLOWED_ORIGINS`
   بالدومين الجديد.
3. في `youcan-config.js`: `mode: 'production'` + المفتاح العمومي
   ديال الإنتاج + رابط `createPayment` (نفس الرابط، إلا تبدل).
4. أعد نشر الدوال، وجرّب أداءً حقيقياً واحداً ببطاقة حقيقية
   (المبلغ كيرجع للبائع ناقص العمولة)، وتأكد من التفعيل والإيميل.
5. من بعد الاختبار الحي، الدفع بالبطاقة كيولي رسمياً متاحاً؛
   التحويل البنكي كيبقى خياراً يدوياً موازياً.

## 6. شنو ما تبناش هنا (عمداً)

- مشغّل الفيديو (Bunny Stream + علامة مائية + منع التحميل): كيجي
  من بعد، ماشي في هاد البناء.
- لوحة تحكم خاصة بالمدفوعات: التتبع حالياً عبر مجموعة
  `payment-events` و`payment-orders` في Firestore + سجلات الدوال.
- حدود معدل الطلبات (rate limiting) على `createPayment`: كتضاف
  منين يقرب الإنتاج إلا دعت الحاجة.
